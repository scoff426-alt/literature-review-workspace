# 七阶段工作流

本文件只说明执行顺序和阶段门禁。字段含义、字数和富文本规则以 `jm-template-writing-spec.md` 为准。

## 阶段 1：初始化与规则识别

1. 读取用户本轮要求、最近的 `AGENTS.md` 和目标工作簿。
2. 确认工作区根目录、canonical Excel、`papers/`、inventory 和知识卡片。
3. 若用户提供范本，先抽取内容、列结构和富文本分布；把范本当作内容密度参考，不盲从其错误或不一致格式。
4. 建立版本化输出目录，不覆盖唯一原件。

验证点：目标文件、表头、论文行数和输出路径均已明确。

## 阶段 2：候选检索与筛选

1. 明确主题边界、语言、期刊层级和年份要求。
2. 新增选文优先 2024 年及以后；较早论文仅在奠基性、不可替代或高度相关时保留。
3. 按论文真实问题判断相关性，不因预设类别而放宽主题门槛。
4. 候选论文与正式论文分开保存。

验证点：每篇候选都有纳入理由、年份和可获取状态。

## 阶段 3：PDF 入库与 inventory 门禁

1. 下载或接收论文 PDF，放入 `papers/`。
2. 打开文件确认不是 HTML、登录页、损坏文件或仅摘要。
3. 更新 `source_inventory.csv`，使 PDF filename 与实际文件一致。
4. 运行项目提供的 PDF gate；没有本地全文的论文留在候选/缺口清单。

验证点：正式论文数量、inventory 行数和真实 PDF 一一对应。

## 阶段 4：全文抽取与来源定位

1. 先用 MarkItDown 抽取全文文本。
2. 对表格、公式、页码、图注或版式缺失部分，用 PDF 专用工具补充。
3. 按九个字段记录事实和来源位置，不先写漂亮总结再倒推引用。
4. 对 Data/Scale、Object/Model、Model/Solution 边界逐项判断。

验证点：每个字段都有原文依据；关键数字可回到页码、章节、图、表或公式。

## 阶段 5：字段写作与知识卡片同步

1. 依据 `jm-template-writing-spec.md` 写 16 列单行记录。
2. 分类按核心问题填写，允许使用四大主题以外的准确类别。
3. 每列只回答本列问题，删去重复和公式堆砌。
4. 逐单元格展开专业缩写，第一次出现写为 `Full Name (ABBR)`；不能跨列继承定义。
5. 同步更新中文知识卡片，确保 Excel、卡片和 PDF 事实一致。

验证点：九个字段无错位，Data 与 Scale 可逐项解释，Innovation 不夸大。

## 阶段 6：富文本与视觉检查

1. `Problem–Results` 为每个非空单元格选择至少一处语义完整重点并设为黑色加粗。
2. `Innovation` 按独立创新点设置红色加粗重点；背景保持黑色常规字。
3. 每个正文字段末尾另起一行添加蓝色、非加粗来源位置，并写完整的 `page / Section / Figure / Table / Equation`。
4. 保持类别无高亮，关键词只加粗 1–2 个。
5. 渲染工作簿，检查换行、截断、行高、列宽、颜色、冻结窗格和整体可读性。

修改既有工作簿时先只处理 1 篇原型。用户确认内容密度和视觉效果后再批量处理。

验证点：原型可直接打开并观察，重点不片面，九列都有覆盖。

## 阶段 7：自动校验、人工抽查与交付

1. 运行 `scripts/validate_workspace.py`；正式交付使用 `--final`。
2. 修复所有 error；逐项确认 warning，而不是机械忽略。
3. 人工抽查分类、关键结论、数值、Data/Scale、创新真实性和来源位置。
4. 比较输出与输入的表结构和基础版式，确认未破坏无关内容。
5. 输出版本化文件、校验报告和简短变更说明；仅在用户要求时替换 canonical 文件。

验证点：校验无错误，人工抽查通过，交付物可打开且能回溯到本地 PDF。

## 返工既有 40 篇工作簿的批次策略

1. 基线审计：只读统计缺失、错位、格式和引用问题。
2. PDF 映射：为每一行记录 PDF 文件名和映射置信度。
3. 单篇原型：完整重建第一篇，渲染并等待用户确认。
4. 小批量：每批完成后运行校验，避免 40 篇错误累积。
5. 全量复核：交叉检查分类、Data/Scale 和 Innovation 红色重点。

任何映射不确定、PDF 缺失或正文证据不足的论文都应单独列出，不得猜测补齐。
